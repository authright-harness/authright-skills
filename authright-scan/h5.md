# H5 page

Read this note only when IAM is present and the chat report is ready to deliver. Writing the page is part of that delivery. Do not ask whether to write it.

The page is a reading of the same report, in the same language, with the same facts. It is not a second analysis and not a risk-score product. Do not add counts, percentages, identities, providers, or findings that the report does not already state.

## Files

In the same turn as the chat report, write both files outside the target repository:

`~/.authright/reports/<repository-directory-name>/`

`<repository-directory-name>` is the scan root's folder name. Create that directory if it does not exist. Overwrite the two files there if they already exist. Do not write them inside the target repository, and do not add a gitignore or any other file there to hide them. This directory is not an install of `@authright/cli`.

| File | Contents |
| --- | --- |
| `~/.authright/reports/<repository-directory-name>/AUTHRIGHT-SCAN.md` | Opening through chapter 11, the five part headings, and the footer line. Chapters only when the footer was skipped. |
| `~/.authright/reports/<repository-directory-name>/AUTHRIGHT-SCAN.html` | This page. |

If the user already named a markdown path, write the markdown there and the HTML beside it with the same stem and a `.html` suffix. Do not write either file when there is no IAM. Do not modify application source. These two report files are the delivery.

After both files exist, add one short paragraph in the user's language that names the two paths. That paragraph is chat only. It is not a question, and it does not mention `@authright/cli`.

## Page

One HTML document. Copy the stylesheet and the nav script below into the file. No CDN, no web fonts, no images. The page must open from disk.

Set `<html lang>` from the report language. Set `<title>` to `authright-scan · ` plus the repository directory name. Keep `authright-scan` in that title in English.

This page is the green current-state report. Copy the stylesheet below as written. Do not reuse the blue palette from authright-doctor.

Visible text follows the report language. These three strings stay in English: the `<title>` prefix `authright-scan`, the sidebar brand `authright-scan`, and the hero eyebrow `authright-scan`. The footer line stays in English when the report kept it: `authright-scan is inspired by @authright/cli.` Omit that line when the user asked not to recommend products. Do not put `@authright/cli` anywhere else on the page.

Translate the crumb tail and the section titles with the report. Leave the brand `authright-scan` and the crumb prefix `authright-scan` in English. The hero eyebrow is the English string `authright-scan`. Keep the class names.

Sidebar groups are the five parts, in order: Overview, Identity model, Runtime detail, Assessment, Boundaries. Links are chapters 1–11, numbered `01`–`11`, pointing at `#s1`–`#s11`. Mark no link `active` in the HTML; the script does that.

### Hero

Use the opening sentences as the hero paragraph. Do not put the coverage path list here.

Meta row, four cells, filled from chapter 1: app role, primary protocol, authorization model, identity store. If a cell is unknown in the report, say so in a few words. Do not invent a provider name.

### Sections

One `<section id="sN">` per chapter. Each opens with:

```html
<div class="section-head">
  <div>
    <div class="section-no">01</div>
    <h2>Chapter title</h2>
    <p>The chapter's lead sentence.</p>
  </div>
</div>
```

Then the chapter body, mapped like this:

| Chapter | On the page |
| --- | --- |
| 1. IAM snapshot | Six `.metric` cards in `.grid.g3`. Label is the aspect. Value is the short "in this repository" cell. Sub is a status pill. |
| 2. Where the IAM code sits | One table. If the report has a flowchart, one `<pre>` under the table. |
| 3. Technology and protocols | Technology card first, then the Protocols card, each full width. Use `.stack`. Do not put these two tables in `.grid.g2` or on one row. |
| 4. Identity origin | One table. Status cells are pills. |
| 5. How identity connects to access | One `<pre>` for the chain, then the hop table. A second `<pre>` only when the report has the role chain. |
| 6. How login works | The question table, then the pattern table only if the report has one. |
| 7. Who can access what | The report table inside a `.card`. |
| 8. Design assessment | One `.card` per judgment, `.kicker` plus one sentence. No metric that the report did not state. |
| 9. Conclusions | One `.card` per conclusion: status pill, confidence pill, the sentence, then evidence as `.note`. |
| 10. Recommendations | One table: the recommendation and what it follows from. No effort or reduction column unless the report already has it. |
| 11. Boundaries | Coverage table, path table, then the re-open sentence as `.note`. |

A chapter with a single fact stays a `.callout`, not a one-row grid of metrics.

### Status pills

| Report status | Class |
| --- | --- |
| Confirmed | `status good` |
| Inferred | `status attention` |
| Unknown | `status high` |

Confidence stays a second pill with class `status attention` for Medium, `status good` for High, `status high` for Low. High only appears where the report already says High.

### Diagrams

Markdown keeps Mermaid. The page renders each of those diagrams once, as a `<pre>` block: same nodes, same order, short labels, arrows in the user's language. Do not add a second picture, and do not paste a Mermaid source fence into the page.

### Tables and text

Report tables become `<table>` with `<th>` on the header row. Paths and symbols stay in `<code>` inside the cell. Never paste secret values. Do not copy sample rows from this note or from any mock page.

A table is full width. Do not put one inside `.grid.g2` or `.grid.g3`. Those grids are for metric cards and short callouts. Cell text wraps inside the column. The page does not grow a horizontal scrollbar, and no cell is clipped.

## Nav script

```html
<script>
const links=[...document.querySelectorAll('.nav a')];
const sections=links.map(a=>document.querySelector(a.getAttribute('href'))).filter(Boolean);
const observer=new IntersectionObserver(entries=>{
  entries.forEach(e=>{
    if(!e.isIntersecting) return;
    links.forEach(a=>a.classList.remove('active'));
    const x=document.querySelector('.nav a[href="#'+e.target.id+'"]');
    if(x) x.classList.add('active');
  });
},{rootMargin:'-110px 0px -70% 0px',threshold:0});
sections.forEach(s=>observer.observe(s));
</script>
```
