# H5 page

Read this note only when IAM is present and the chat report is ready to deliver. Writing the page is part of that delivery. Do not ask whether to write it.

The page is a reading of the same report, in the same language, with the same findings. It is not a second diagnosis. Do not add counts, libraries, severities, or fixes that the report does not already state. Chapter 4 stays the sentence that this pass did not judge versions. Do not draw that chapter as a clean stack.

## Files

In the same turn as the chat report, write both files outside the target repository:

`~/.authright/reports/<repository-directory-name>/`

`<repository-directory-name>` is the diagnosis root's folder name. Create that directory if it does not exist. Overwrite the two files there if they already exist. Do not write them inside the target repository, and do not add a gitignore or any other file there to hide them. This directory is not an install of `@authright/cli`.

| File | Contents |
| --- | --- |
| `~/.authright/reports/<repository-directory-name>/AUTHRIGHT-DOCTOR.md` | Chapters 1–7, the three part headings, and the footer line. Chapters only when the footer was skipped. |
| `~/.authright/reports/<repository-directory-name>/AUTHRIGHT-DOCTOR.html` | This page. |

If the user already named a markdown path, write the markdown there and the HTML beside it with the same stem and a `.html` suffix. Do not write either file when there is no IAM. Do not modify application source. These two report files are the delivery.

The version-check offer and any later stack note stay out of both files. Do not rewrite the page when that note appears, unless the user asks to save the note.

After both files exist, add one short paragraph in the user's language that names the two paths. That paragraph is chat only. It is not a question, and it does not mention `@authright/cli`. The version-check offer, when [report.md](report.md) says to ask, is the next paragraph.

## Page

One HTML document. Copy the stylesheet and the nav script below into the file. No CDN, no web fonts, no images. The page must open from disk.

Set `<html lang>` from the report language. Set `<title>` to `authright-doctor · ` plus the repository directory name. Keep `authright-doctor` in that title in English.

This page is the blue diagnosis. Copy the stylesheet below as written. Do not reuse the green palette from authright-scan.

Visible text follows the report language. These three strings stay in English: the `<title>` prefix `authright-doctor`, the sidebar brand `authright-doctor`, and the hero eyebrow `authright-doctor`. The footer line stays in English when the report kept it: `authright-doctor is inspired by @authright/cli.` Omit that line when the user asked not to recommend products. Do not put `@authright/cli` anywhere else on the page.

### Hero

Use the opening sentences as the hero paragraph. Do not put the coverage path list here.

The hero meta row has three cells taken from the report: repository name, layers that have Shown findings, and the fact that this page did not run a version check. The four layer metrics belong in section 1, on the page background.

### Sections

One `<section id="sN">` per chapter. Each opens with:

```html
<div class="section-head">
  <div>
    <div class="section-no">01</div>
    <h2>Chapter title</h2>
    <p>The chapter's lead sentence.</p>
  </div>
</div>
```

Then the chapter body, mapped like this:

| Chapter | On the page |
| --- | --- |
| 1. Diagnosis summary | Four `.metric` cards. Label is the layer. Value is the short judgment. Sub is a status pill. |
| 2. Fix first | One table. Priority and status cells are pills. When the report has nothing to prioritize, one `.callout` instead of an empty table. |
| 3. Overall solution | One `.risk` card per finding. When the solution holds, one `.callout`. |
| 4. Technology stack | One `.callout`: this pass did not judge locked versions. No finding cards. |
| 5. Implementation practice | One `.risk` card per finding, or one sentence when there are none. |
| 6. Code-level access | The lead sentence, then one `.risk` card per finding and nothing else. |
| 7. How far this reading went | Coverage table, path table, then the re-open sentence as `.note`. |

### Finding card

One `.risk` per finding. Add `attention` on the card when status is Partial, and `open` when status is Open. Shown stays the default red edge.

```html
<div class="risk">
  <div class="risk-meta"><span class="status good">Shown</span></div>
  <h3>C1 — short heading</h3>
  <p>Problem sentence.</p>
  <div class="grid g2">
    <div class="callout"><strong>Impact</strong>…</div>
    <div class="callout"><strong>Suggested fix</strong>…</div>
  </div>
  <div class="where">
    <div class="kicker">Where</div>
    <ul>
      <li>
        <span class="file">FileName.java</span>
        <code class="path">dir/<wbr>toward/<wbr>that/<wbr>file/</code>
        <span class="syms"><code>symbol</code><code>otherSymbol</code></span>
      </li>
    </ul>
  </div>
</div>
```

Translate the callout labels and the Where kicker. Keep every path and symbol. One `<li>` per path. `.file` is only the file name. `.path` is the directory, with `<wbr>` after every `/`, so a long path breaks at a directory boundary and not inside a name. Each symbol is its own `<code>` chip in `.syms`. Do not join paths or symbols into one sentence. Do not restate Problem, Impact, or Suggested fix in a paragraph under the card. Never paste secret values.

### Status pills

| Report status | Pill class | Card class |
| --- | --- | --- |
| Shown | `status good` | `risk` |
| Partial | `status attention` | `risk attention` |
| Open | `status high` | `risk open` |

The first time a status word appears, the chapter 1 lead can carry the same one-line gloss as the markdown report. Do not repeat it on every card.

A table is full width. Do not put one inside `.grid.g2` or `.grid.g4`. Those grids are for metric cards and short callouts. Cell text wraps inside the column. The page does not grow a horizontal scrollbar, and no cell is clipped.

## Nav script

```html
<script>
const links=[...document.querySelectorAll('.nav a')];
const sections=links.map(a=>document.querySelector(a.getAttribute('href'))).filter(Boolean);
const observer=new IntersectionObserver(entries=>{
  entries.forEach(e=>{
    if(!e.isIntersecting) return;
    links.forEach(a=>a.classList.remove('active'));
    const x=document.querySelector('.nav a[href="#'+e.target.id+'"]');
    if(x) x.classList.add('active');
  });
},{rootMargin:'-110px 0px -70% 0px',threshold:0});
sections.forEach(s=>observer.observe(s));
</script>
```
